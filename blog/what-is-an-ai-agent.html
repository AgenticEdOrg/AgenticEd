What is an AI agent, really? A plain-English guide

AgenticEd TeamOct 8, 20266 min read

"Agent" might be the most overused word in technology right now. Product launches call everything an agent: chat assistants, automated email rules, even search boxes. That makes it hard for students, teachers, and decision-makers to know what they're actually looking at. This guide gives you one simple test and a handful of everyday examples so you can tell the difference.

The one-question test

Ask: who decides what happens next?

  • If nothing happens next — you ask, it answers, done — it's a chatbot (or a single AI call).
  • If a developer decided the steps in advance — "every night, summarize new tickets, then email the manager" — it's a workflow, even if AI is used inside it.
  • If the AI itself decides the next step based on what it has seen so far, it's an agent.
An agent is software that pursues a goal over several steps, choosing its own next action based on what it observes.

The loop at the heart of every agent

Every agent, from a research assistant to a coding tool, runs the same cycle: Think → Act → Observe. It reasons about the goal, takes an action (search the web, read a file, run a calculation, send a message), looks at the result, and decides what to do next. It repeats until the goal is met, it gets stuck, or it hits a limit someone set for it.

A navigation app is a helpful everyday picture. It doesn't compute one route and stop. It keeps watching traffic and changes the plan when conditions change. That continuous observe-and-adapt behavior is what makes something agentic.

What agents are made of

Under the hood, nearly every agent has the same five parts:

  1. A model — the large language model that does the reasoning.
  2. Instructions — a system prompt describing its role, goal, and rules.
  3. Tools — things it can call: search, calculators, databases, calendars, email.
  4. Memory — what it can see right now, plus anything saved for later sessions.
  5. Orchestration — the code that runs the loop, enforces limits, and asks a human for approval when needed.

Autonomy is a dial, not a switch

"Autonomous" doesn't mean "unsupervised". A useful way to think about it is a dial: an assistant only suggests; a copilot drafts and you approve each step; a supervised agent acts on low-risk steps and asks before risky ones; a fully autonomous agent works end to end inside boundaries you set, with monitoring.

Rule of thumb: match the autonomy to the stakes. An agent tidying your notes can be highly autonomous. An agent that sends messages to other people or spends money should ask first.

Why the distinction matters

Agents are powerful precisely because they act. That also means their mistakes are actions, not just wrong sentences. When you know you're dealing with an agent, you know to ask the right questions: What can it do? What can't it undo? Where does a human check its work?
